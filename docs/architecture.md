# Architecture

PDF Tools uses a React client, a Spring Boot API, PostgreSQL job metadata, and
streaming artifact storage.

## Request flow

1. The client submits multipart input to `POST /api/v1/jobs`.
2. The API validates operation metadata before streaming each file into storage.
3. PostgreSQL records the job and ordered input metadata.
4. A bounded worker pool materializes inputs into an isolated temporary workspace.
5. A registered operation writes one or more outputs inside that workspace.
6. Outputs stream into artifact storage and appear in the job's `outputs[]`.
7. The client receives progress through server-sent events and downloads outputs by ID.
8. Anonymous input and output artifacts expire two hours after a terminal result.

No v1 API accepts a storage filename as a download path. Job and output UUIDs are
resolved through metadata, and response bodies stream without whole-file byte arrays.
Pending jobs are redispatched from PostgreSQL after queue pressure or restart. Workers
own renewable database leases; only expired leases become explicit failures. Uploads
use a committed `UPLOADING` state so object cleanup cannot race active requests.
Each replica polls persisted job versions for its local SSE subscribers, so updates
cross process boundaries without sticky sessions. Lease renewal runs on a dedicated
scheduler isolated from storage cleanup.

## Backend modules

| Package | Responsibility |
| --- | --- |
| `jobs` | Job lifecycle, persistence, progress, cancellation, expiry, and API DTOs |
| `operations` | Operation contract, registry, execution context, outputs, and ZIP creation |
| `operations.shared.pages` | Shared page-expression grammar and duplicate policy |
| `operations.shared.coordinates` | Normalized preview-to-PDF coordinate conversion |
| `operations.shared.queue` | Durable one-way sidecar queue protocol and lifecycle |
| `storage` | Local filesystem and S3-compatible streaming adapters |
| `api` | Structured HTTP error contract |
| `service` | Legacy `/api/pdf` implementation retained during migration |

Each operation is a `PdfOperation` bean with a unique kebab-case key. A route is
usable only when both its implementation is registered and its key appears in
`pdf.jobs.enabled-operations`. This keeps incomplete tools deployable but inaccessible.

## Storage

Development defaults to `LocalStorageService`. It writes through a temporary file,
checks the byte count, computes SHA-256 while streaming, and atomically moves the
artifact into place.

Production can select `S3StorageService` with `PDF_STORAGE_TYPE=s3`. The adapter uses
path-style access for SeaweedFS and also works with compatible S3 endpoints. Production
credentials must come from the deployment secret store; they are not committed.

## Persistence

Flyway owns the PostgreSQL schema:

- `pdf_jobs` stores state, progress, structured failure fields, cancellation, and expiry.
- `pdf_job_inputs` stores deterministic input order and immutable object metadata.
- `pdf_job_outputs` stores ordered downloadable artifacts.

Foreign keys cascade metadata deletion. Object deletion happens first so failed storage
cleanup remains retryable.

Output metadata and the `COMPLETED` transition commit atomically. Non-completed jobs do
not expose outputs. A grace-period orphan scan removes objects left by process failure
before a metadata transaction could commit.
Jobs and outputs share one terminal expiry instant, and access is rejected at that
instant independently of cleanup success. Recovery also removes stale per-job
workspaces left by an interrupted process.

## Coordinates

The editor exchanges normalized rectangles with a top-left origin relative to the
visible crop box. The backend converts these to PDF user space while accounting for
crop-box offsets and page rotations of 0, 90, 180, or 270 degrees.

## Security and resource boundaries

- Multipart parts spill to disk immediately.
- Text metadata parts are byte-bounded before UTF-8 decoding.
- Per-file and per-job file-count limits are enforced before execution.
- Aggregate multipart requests are capped at 100 MB for both legacy and v1 routes.
- Workers use a bounded thread pool and isolated temporary directories.
- Streaming downloads use a separate bounded MVC executor and a two-hour timeout.
- Storage keys are generated by the server and normalized under a configured root.
- Office conversion uses a networkless sidecar with a root queue supervisor and
  distinct non-root LibreOffice/POI workers.
- HTML conversion uses a separate networkless, read-only Playwright sidecar with
  a non-root Chromium sandbox, version-matched seccomp policy, tmpfs, and cgroup
  limits.
- The backend container itself runs as an unprivileged user.
